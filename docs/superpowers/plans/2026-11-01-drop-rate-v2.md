# Drop Rate V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new `/drop-rate-v2` (beta) tracker that computes the game's Drop Rate (`TotalStats("Drop_Rarity")`) from scratch on the statTracker kit — tree, Biggest Gains, Compare (with an Arcane toggle), History — with a per-class-family Observed Max, leaving the V1 page and code untouched.

**Architecture:** Extend the kit's grouped descriptor with ordered `add`/`replace` steps; a new `dr2` system with one id per N.js term that delegates to the existing catalog resolvers (read-only) and names nodes like the game; an entry point + collector + page wired like `lib/artifactFind`.

**Tech Stack:** TypeScript, Next.js app router, vitest + @testing-library/react, tsx scripts.

**Spec:** `docs/superpowers/specs/2026-11-01-drop-rate-v2-design.md`

## Global Constraints

- N.js (`web/scripts/updater/.cache/N.new.js`; the root `N.js` is stale) is the only source of truth; every new port carries an `@njs` tag (registry guard green: `npx tsx scripts/updater/registry/gen-registry.ts` then `npx vitest run __tests__/updater/registry.guard.test.ts`).

- Node names: `"<game name> (<Source> N)"`, jargon in the node `note`; never " / " in a name; keep `(Talent n)` suffixes.
- Site copy in English; replies to the user in Portuguese.

- Dungeon formula out of scope.
- Branch `feat/drop-rate-v2`; stage only touched files; each commit ends with exactly one trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; never merge to main without an explicit request; never run `npm run dev`.
- All commands from `web/`.

## Review Focus

1. Chip floor only applies below 5 and never pushes past 5 (`min(5, x + chip/100)`). Pinned in Task 1.
2. Cove replaces the whole total only on map 216 with `Holes[0][char] == 17`; elsewhere `replace` is a no-op. Pinned in Tasks 1 and 3.
3. Biggest Gains what-if replays the same step order as the tree (an `add` after a `mult` is not commutative). Pinned in Task 1 (`totalFromFlat` equals `combine` on the same pools).
4. Turning the Arcane toggle off removes only the Arcane group and recomputes the reference root exactly. Pinned in Task 2.
5. A save with no Research / companions / tome still totals ≥ 1 without NaN. Pinned in Task 4 (smoke on empty envelope).

### Task 1: Kit — ordered `add` / `replace` steps

**Files:**
- Modify: `lib/arkh/stats/defs/grouped.ts`
- Modify: `lib/statTracker/biggestGains.ts` (`DISPLAY`, `groupedGainsModel.totalFromFlat`)
- Test: `__tests__/lib/arkh/grouped.test.ts`, `__tests__/lib/statTracker/biggestGains.test.ts` (or the existing grouped gains test)

**Interfaces:**
- Produces: `GroupKind = "pct" | "raw" | "min4" | "mult" | "add" | "replace"`; `StatGroup.below?: number`; `applyGroupStep(g, vals: readonly number[], total: number): number` exported from `grouped.ts` and used by BOTH `groupedDescriptor.combine` and `groupedGainsModel.totalFromFlat`. Semantics: `pct/raw/min4/mult` → `total × groupFactorOf(g, vals)` (unchanged); `add` → `total + Σ`, with `below` → `total < below ? Math.min(below, total + Σ) : total`; `replace` → only the first finite value > 0 in `vals` replaces `total` (a replace source is always emitted, 0 when it doesn't apply — never omitted or NaN); else `total`. `neutralValue("add") = 0`, `neutralValue("replace") = 0`. The group node's `val` in the tree: the factor for multiplicative kinds, `Σ` for `add`, the replacement (or NaN, shown as "—", when none applies) for `replace`; `groupNote` gets `"+ Σ"`, `"+ Σ (only below N, capped at N)"`, `"replaces the total"`. `DISPLAY.add = DISPLAY.replace = "raw"`.

- [ ] **Step 2: Run** `npx vitest run __tests__/lib/arkh/grouped.test.ts` → FAIL.
- [ ] **Step 3: Implement.**
- [ ] **Step 4: Run** the two test files and the existing tracker smoke/combine tests (`__tests__/lib/arkh/*smoke* *combine*`) → PASS.
